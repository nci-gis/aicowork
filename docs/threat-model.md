# Threat model — AI-Cowork

_Moved here from `SECURITY.md` on 2026-10-10: the root page states what is claimed and not claimed; this page is the one-page model behind it. Threat numbers are referenced from other documents; they do not change._

**Assets**: work data (possibly confidential), family and personal data, the egress policy, personas, skills and instruction files (they steer the agent), the receipt log, git history.

**Actors**: the owner; an external sender of mail or documents (**the main threat**); authors of malicious skills, plugins or dependencies; a web page open in the owner's browser (attacks on localhost); another local process; a mistaken or manipulated agent.

**Trust boundaries**: (1) outside world → `00_inbox/` · (2) inbox content → the model's context (the injection boundary) · (3) model → tools (the host's permission boundary) · (4) files → the egress gate · (5) browser → viewer · (6) machine → the model provider (the approved AI surface) · (7) release artifacts → a new user.

**Top threats and the controls against them**

| #   | Threat                                                                                             | Controls (kernel / tools)                                                                                                                                                                                                                                                                                                                                                                            | Residual risk                                                                                                                                 |
| --- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Injected text in a mail edits the policy, a persona, a skill or the instruction file (persistence) | untrusted markers with an unguessable nonce (`ingest`); "untrusted content is data" in the instruction file and skills; post-session `audit` flags any protected-file change; kernel manifest drift in `doctor`; INDEX titles are the agent's own words (L2-INDEX-CLEAN); the trust anchor binds every steering file and egress refuses on drift (L2-POLICY-BOUND)                                   | the model may still follow an injection within the session; a change to a steering file stops egress but is otherwise detected after the fact |
| 2   | Injection makes the agent send data out (upload, image URL, link)                                  | the reach rule (the folder = what the model sees); IT settings for the host (`hosts/*-hardening.md`: ask on `curl`, egress allow-list); manual approval for triage; the viewer never loads remote images                                                                                                                                                                                             | depends on host settings the kernel cannot enforce                                                                                            |
| 3   | Excessive agency: mass moves, deletes, overwrites                                                  | never-delete (audit fails on any delete); plan-then-apply with path allow-lists and caps (`triage --apply`); exclusive create in capture                                                                                                                                                                                                                                                             | a host that allows delete can still delete; git history recovers it                                                                           |
| 4   | Private files leave the machine by mistake                                                         | per-file `visibility` fail-closed; a file leaving the inbox is made private by the executor; egress only through `policy.yaml` (strict validation, NEVER_EXPORT, private blocks stripped mechanically) and only while the policy matches the owner's anchor; the content check matches owner names after normalisation (L2-LEAK-NORM); hash-chained receipts; pre-push hook refuses unlisted remotes | a human can always copy files by hand; obfuscation beyond the normalisation layers (see below)                                                |
| 5   | A web page attacks the viewer (DNS rebinding, CSRF)                                                | Host allow-list (421), per-launch session cookie, same-origin JSON writes, loopback bind enforced at start                                                                                                                                                                                                                                                                                           | none known for the tested cases                                                                                                               |
| 6   | Stored XSS from a note or mail                                                                     | raw HTML escaped, URL schemes allow-listed, snippets escaped, strict `script-src 'self'` CSP, no inline handlers                                                                                                                                                                                                                                                                                     | CSS injection via inline styles is still possible (low impact)                                                                                |
| 7   | Malicious skill, dependency or vendored JS                                                         | kernel ships first-party skills only, hash-locked by the manifest; skills lint forbids network commands and blobs; locked dependencies with upper bounds; SBOM; kernel artifact contains no code                                                                                                                                                                                                     | the host's own plugin/skill store is out of scope                                                                                             |
| 8   | A cloned repo runs code on open                                                                    | the kernel runs nothing on open; hooks are opt-in (`core.hooksPath`) and never auto-installed                                                                                                                                                                                                                                                                                                        | a host that auto-runs repo config is out of scope                                                                                             |
| 9   | Path traversal, symlink/junction escape                                                            | `safe_path` rejects `..`, absolute/UNC/drive, ADS, device names, and anything redirected after resolution; roots checked after resolution; a symlink inside the folder is reported (L2-REACH-LINK) and never followed by scans, export or the viewer                                                                                                                                                 | TOCTOU between check and open on a hostile local filesystem; the agent host itself may follow a link                                          |
| 10  | Tampering with the audit trail or history                                                          | receipts hash-chained; manifests; the trust anchor (commit + hashes) stored outside the folder, written by the owner on the host — the tools refuse to write it from an agent sandbox or a mounted folder; rewritten history is detected by `doctor`                                                                                                                                                 | tamper-**evident**, not tamper-proof: whoever can write the user profile can move the anchor                                                  |
