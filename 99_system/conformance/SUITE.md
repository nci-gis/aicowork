# Conformance suite — what "a proper AI-Cowork" means

_Kernel. Any tool may implement a runner for these cases; the reference runner is `aicowork conform`. A case ID never changes meaning; a new rule gets a new ID._

An instance **conforms at level N** when no case at level ≤ N reports an error. Warnings are reported but never fail.
A **kernel release** conforms when its example instance (`fixtures/example-instance/`, checked together with the kernel) passes L2.

| ID             | The instance must…                                                                                                                                                                                                                                                                                                                                                                                                   | Error when                                                                                                                                                                                    |

## Session audit (between two commits)

Run after any agent session, host-side (reference: `aicowork audit --since <commit> [--task triage|brief|weekly]`):

| ID                | Error when                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| AUDIT-DELETE      | a file was deleted (moves are fine; never delete)                                                                                                 |
| AUDIT-PROTECTED   | the kernel, the tools, `policy.yaml`, `aicowork.yaml`, the instruction file, `me.md`, lock files or hooks changed — the owner confirms or reverts |
| AUDIT-SCOPE       | with `--task`, a file outside what that task may write changed                                                                                    |
| AUDIT-VIS-RAISE   | a file's `visibility` went up, or a new file was created above `private`                                                                          |
| AUDIT-FRONTMATTER | a changed content file breaks L1-FRONTMATTER                                                                                                      |
| AUDIT-MARKERS     | a changed file's untrusted markers no longer pair up                                                                                              |
| AUDIT-MANIFEST    | a manifest no longer matches                                                                                                                      |

## Running the suite by hand

No runner is required. For L1/L2 an agent or a person checks each row literally: walk the folders named in the case; parse frontmatter with the YAML subset (CONVENTIONS "Instance config" — an empty value is unset); match host names and `check_tokens` case-insensitively (a one-word token as a whole word, a phrase as a substring); count words as whitespace-separated runs in the files the case names; check `MANIFEST.sha256` with any sha256 tool. Report each case ID as pass/fail with the path that failed, in `06_logs/conformance/YYYY-MM-DD_by-hand.md`. Host-name patterns to match are in `conformance/fixtures/host-names.txt` (a fixture, so the suite does not name hosts itself). Scope: L2-OWNER and L2-HOST-NAMES cover the kernel ring minus `fixtures/`; L2-MARKERS covers the content folders `00_`–`10_`; an untrusted pair matches by id (each id opens once and closes once).

## L3 — Behaviour (an agent runs a skill; a runner scores the result)

Protocol for every L3 case: (1) copy the example instance to a temp folder, `git init`, commit; note the commit; (2) put the case's fixtures in place; (3) open the folder in the host and say the case's prompt, in manual-approval mode; (4) score with the runner; (5) record date, host, host version, model, result and every question the agent asked in `06_logs/conformance/YYYY-MM-DD_<case-id>.md` (no frontmatter needed; commit `log:`).
