# Claude Cowork — hardening guide for IT / MIS

_Ring: host adapter. The kernel **states** the platform settings it assumes; IT **enforces** them. Setting names are from Anthropic's Claude Desktop configuration and admin documentation, read 2026-10-01 — **re-verify names before applying**; they change between releases._

AI-Cowork keeps the owner's work and life notes as plain files in one local folder that is connected to Claude Cowork. The kernel cannot stop the agent from reading what is in that folder, or from using tools the platform allows. These settings close the gaps the kernel cannot close itself.

| Setting (MDM / admin)                                                    | Recommended value                                                                                                        | Threat it addresses                                         | Kernel side                                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `allowedWorkspaceFolders`                                                | only the AI-Cowork folder (and any reference folders as `ro`)                                                            | agent reading unrelated drives/home folders                 | CONVENTIONS "Reach": the folder is the boundary                                               |
| `builtinToolPolicy`                                                      | `Bash(curl *)`, `Bash(wget *)`, `Bash(Invoke-WebRequest *)` → **ask**                                                    | prompt-injection exfiltration by upload (reported Jan 2026) | untrusted markers; audit after session                                                        |
| network egress (Code execution → network egress)                         | "Package managers only", or an explicit allow-list; add `coworkEgressAllowedHosts` / `egressProxyUrl` as policy requires | data leaving through the VM's network                       | our own tools make no network calls (test `test_nonet.py`)                                    |
| `disabledBuiltinTools`                                                   | disable tools the org does not use (e.g. computer use, browser)                                                          | broader reach than needed                                   | operating modes in the host page                                                              |
| `disableBypassPermissionsMode`                                           | `disable`                                                                                                                | a user or injected text switching off approvals             | manual approval for triage                                                                    |
| `scheduledTasksEnabled`                                                  | on only if rituals are wanted                                                                                            | unattended runs with less oversight                         | task specs touch only `06_logs/` + `INDEX.md`                                                 |
| `userPluginUploadsEnabled`, `skillCreationEnabled`                       | off, or review policy                                                                                                    | malicious skills/plugins (supply chain)                     | kernel skills are hash-locked (`99_system/MANIFEST.sha256`); stubs only point into the folder |
| Connectors                                                               | only those approved; "always allow" for write-capable tools stays off                                                    | a connector as an egress path                               | reach report lists approved AI surfaces                                                       |
| OpenTelemetry / Compliance API                                           | on; set content capture **explicitly** (`otlpContentCapture`) — the default is documented inconsistently                 | no audit trail of agent actions                             | plain-text audit in the folder (`06_logs/audit/`)                                             |
| Session retention (`coworkSessionRetentionDays`, `sessionRetentionHold`) | per records policy                                                                                                       | local transcripts outliving the notes                       | retention report (`aicowork retention`)                                                       |
| Cloud vs local sessions                                                  | decide explicitly (cloud default from 2026-10-06 for Pro/Max)                                                            | where file contents are processed                           | the model call is the named egress                                                            |

## Questions the owner has asked IT (record answers in `09_decisions/`)

1. Is Cowork on local or cloud mode for our org? Which approved AI surfaces may read work data?
2. Is `allowedWorkspaceFolders` set? Is the egress allow-list set?
3. Are Compliance API / OpenTelemetry on, and is content captured?
4. Does a company OneDrive or network share count as in-tenant for backups?
